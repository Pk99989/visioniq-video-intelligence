# Phase 1 VLM benchmark — 2026-11-06

Real vision-model inference, end to end, on this machine (Linux VM,
CPU-only, 7.9 GB RAM). Model: **moondream** (1.86B params, Q4_0,
1.7 GB) via Ollama 0.40.15. `llava:7b` remains the configured model
for the user's RTX 3050 — moondream is the verified CPU alternative
for this VM, per the upgrade plan's "verified alternative" rule.

## Method

`scripts/vlm_e2e.py`: upload the 10 s bus sample video through the
real API (`SYNC_PROCESSING=1`, hash embeddings), read the stored
caption from the DB, then search "bus". VLM config:
`VLM_PROVIDER=ollama`, `VLM_MODEL=moondream`,
`VLM_BASE_URL=http://localhost:11434/v1`, timeout 300 s, 2 retries.

## Results

| Step | Observed |
|---|---|
| Direct model call (first load) | 228.1 s, model loads + 1 inference. Description correct ("two people walking on a sidewalk next to a blue bus"), but `objects` came back as malformed dicts with repeated "stop name" values — the parser discarded the non-string objects and kept the description. |
| Pipeline upload → ready (model warm) | **17.5 s** (5 frames, 1 scene, 25 detections) |
| Stored caption | `provider='ollama'`, `model='moondream'` — genuine description: "three people walking on the sidewalk near a blue and white bus… one wearing a red shirt… potted plants visible in the scene". |
| Search "bus" | **0.865**, returning the VLM caption |

## Honest notes

- **Structured JSON compliance is model-dependent.** Moondream
  returned JSON once and plain prose once for the same prompt. The
  parser handles both (JSON → structured fields; prose → description
  only). `llava:7b` on the GPU machine is expected to follow the
  JSON schema more reliably; that run is still to be done on the
  user's RTX 3050.
- **First-load latency is high on CPU** (228 s including model load
  from disk). Warm inference is ~15–20 s per frame on this VM.
  VLM timeout (120 s default, 300 s in this run) + 2 retries cover
  a cold start; on the laptop, `llava:7b` on GPU will be much faster.
- **Model download needed a workaround on this VM:** `ollama pull`
  times out against the egress proxy, so the blobs were fetched with
  curl and the manifest installed manually (`scripts` note in
  `~/tmp/e2e/fetch-moondream.sh`). Not a product issue — the user's
  laptop pulls normally.
- Captions are stored with `provider` + `model`, and the frontend
  already shows the provider next to each caption, so a VLM caption
  can never be mistaken for a template.
